# ЛР №7. Програмний брандмауер (user-space проксі TCP/UDP)

Навчальний брандмауер, що працює **без прав адміністратора**: клієнти підключаються не до цільового сервера,
а до проксі-порту брандмауера, який перевіряє кожне з'єднання (TCP) або датаграму (UDP) за таблицею правил
і або пропускає його далі, або відхиляє. Усі рішення записуються в журнал.

## Файли
| Файл | Призначення |
|---|---|
| `firewall.py` | сервіс брандмауера: проксі TCP/UDP + Admin API + журнал |
| `fwctl.py` | консольний інтерфейс керування правилами |
| `analyze_logs.py` | пошук і аналіз журналу |
| `config.json` | сервіси (які порти слухаємо і куди пересилаємо), початкові правила |

## Запуск
```
python firewall.py --config config.json
```
Admin API доступний лише локально: `http://127.0.0.1:8081`. Сервіси за замовчуванням:
TCP `0.0.0.0:8080 -> example.org:80`, UDP `0.0.0.0:5353 -> 8.8.8.8:53`.

## Структура правила
| Поле | Тип | Опис |
|---|---|---|
| `id` | int | унікальний номер (призначається автоматично) |
| `priority` | int | **менше число = вищий пріоритет**; перше правило, що підійшло, вирішує долю пакета |
| `action` | `allow` / `deny` | пропустити / відхилити |
| `src_ip_cidr` | рядок | IP або підмережа джерела (напр. `26.147.33.195/32`, `192.168.0.0/16`) |
| `dst_ip_cidr` | рядок | IP або підмережа призначення |
| `src_port`, `dst_port` | int | порт; `0` = будь-який |
| `proto` | `TCP` / `UDP` | протокол |
| `enabled` | bool | `false` = правило тимчасово вимкнене (не діє, не бере участі в конфліктах) |
| `comment` | рядок | довільний опис |

Якщо жодне правило не підійшло - діє **політика за замовчуванням: allow**.

## Керування без перезапуску
Консоль:
```
python fwctl.py list
python fwctl.py add --action deny --src 26.147.33.195/32 --proto TCP --priority 10 --comment "блок ноутбука"
python fwctl.py disable 1      # вимкнути
python fwctl.py enable 1       # увімкнути
python fwctl.py delete 1       # видалити
python fwctl.py conflicts      # аналіз усього набору правил
python fwctl.py reload         # перечитати правила з config.json
```
HTTP API: `GET /rules`, `POST /rules`, `PATCH /rules/<id>`, `DELETE /rules/<id>`, `GET /conflicts`, `POST /reload`.
Зміни діють негайно - наступне ж з'єднання перевіряється за оновленою таблицею.

## Журнал (`logs/events.jsonl`, JSON Lines)
Один рядок = одна подія. Поля трафіку: `time` (локальний час), `ts` (unix), `event` (`tcp.connect`, `udp.packet`),
`proto`, `src_ip`, `src_port`, `dst_ip`, `dst_port`, `action` (`allow`/`deny`), `rule_id`, **`reason`** (причина).
Дії адміністратора: `admin.rule_add`, `admin.rule_update`, `admin.rule_delete`, `admin.rule_rejected`, `admin.reload`.

Пошук: `python analyze_logs.py --action deny --src 1.2.3.4 --proto TCP --since "2025-12-01 10:00:00"`;
зведена статистика - `python analyze_logs.py`.

## Виявлення та вирішення конфліктів
Два правила **перекриваються**, якщо існує пакет, що підпадає під обидва (однаковий протокол, підмережі
джерела/призначення перетинаються, а порти збігаються або хоча б один з них `0`). Перевірка виконується при кожному
додаванні/зміні правила та на вимогу (`GET /conflicts`). Вимкнені правила в конфліктах не беруть участі.

| Ситуація | Реакція |
|---|---|
| Однакові умови і та сама дія | **відхиляється** (`duplicate_rule`, HTTP 409) |
| Однакові умови, різні дії, **однаковий пріоритет** | **відхиляється** (`conflict_same_priority`) - результат неоднозначний |
| Перекриття, різні дії, **однаковий пріоритет** | **відхиляється** (`overlap_same_priority`) |
| Однакові умови, різні дії, різний пріоритет | додається + попередження `conflict_shadowed`: переможе правило з меншим числом пріоритету, друге ніколи не спрацює |
| Часткове перекриття, різні дії, різний пріоритет | додається + попередження `overlap_conflict`: у спільній частині переважає вищий пріоритет |

**Вирішення:** детермінований порядок - правила відсортовані за `priority`, перше що підійшло, спрацьовує;
неоднозначні випадки (однаковий пріоритет) не допускаються. Користувач може змінити пріоритет (`PATCH`),
вимкнути або видалити одне з правил.

## Обмеження
Це user-space проксі, а не фільтр пакетів ядра: керує лише трафіком, що йде через його порти.
Для реальних систем використовують nftables / Windows Filtering Platform / PF / eBPF.
